В Go (в стандартном пакете net/http) часто встречаются три «таймаута», два из которых вы, видимо, имеете в виду:
ReadTimeout
– максимальное время на чтение HTTP-заголовков (Request) от клиента.
– если клиент не присылает данные в течение этого периода, соединение закрывается.
WriteTimeout
– максимальное время на запись ответа (Response) клиенту.
– включает и сериализацию тела ответа, и отправку по сети.
IdleTimeout
– максимальное время «простоя» соединения между двумя запросами при включённом keep-alive.
– если после обработки одного запроса в течение указанного времени от клиента новых данных не поступает, соединение закрывается.

В чистом YAML нельзя напрямую ссылаться на другие поля внутри того же файла — он не поддерживает интерполяцию или шаблоны на уровне синтаксиса. То есть запись address: {host}:{port} не будет автоматически подставлять значения host и port.

Если тебе нужно именно в YAML писать address: ${host}:${port}, тогда можно использовать библиотеку вроде gomplate или envsubst, чтобы предобработать YAML перед загрузкой.

Ниже — список наиболее распространённых «окружений» (environment), которые встречаются в разработке и эксплуатации приложений. Конкретный набор и названия зависят от команды и процесса, но общий смысл примерно такой:

local (локальный)
– вы запускаете приложение у себя на машине, делаете активную разработку и отладку.
development (разработка, dev)
– интеграционная среда для разработчиков. Код собирается автоматически (CI), и туда стягиваются ветки, чтобы проверить на общих данных.
test / qa (тестирование / контроль качества)
– здесь тестировщики/QA проверяют фичи, фиксят баги. Может быть несколько сред (например, test1, test2), если много параллельных задач.
staging / preprod (предпрод)
– максимально приближённая к боевой среда. Там синхронизируют конфигурацию, версии зависимостей и данные с production (обычно анонимизированные). Отсюда — «зелёный свет» для релиза.
production (прод, prod)
– «боевой» (пользовательский) кластер, которым реально пользуются клиенты/пользователи.
uat (User Acceptance Testing)
– специальная среда для заказчика или бизнес-пользователей, чтобы они официально приняли новый функционал перед запуском. Иногда её совмещают со staging.
ci / integration (не путать с CI-сервером)
– среда, куда автоматически выкатываются изменения при каждом коммите для автоматизированных интеграционных тестов.
sandbox (песочница)
– место для экспериментов, обучения, демонстраций, где допускается «сломать всё» без рисков.
demo (демо)
– окружение для презентаций клиентов, партнёров, конференций. Часто с заготовленными тестовыми данными.


env: "development"   # локальная/разработческая среда
env: "staging"       # предпродакшен
env: "production"    # боевой продакшен

При выборе стоит договориться в команде, какие именно значения вы поддерживаете, и описать их в документации:
• local – для локальной разработки
• dev – для интеграционной среды разработчиков
• qa – для тестирования и QA
• staging / preprod – для предпродакшена
• prod – для боевой эксплуатации
• (опционально) uat, sandbox, demo и т. д.

В Go приставка Must в названии функции — это устоявшийся идиоматический стиль, который означает: если что-то пошло не так, вызывается panic вместо возврата ошибки.

⚠️ Что означает Must
Функция с Must не возвращает ошибку, а завершает программу с panic, если что-то пошло не так.
Это удобно, когда ошибка не должна происходить при нормальной работе (например, при инициализации конффига, шаблона, регулярки и т.д.).

📌 Примеры
✅ template.Must
go
tmpl := template.Must(template.New("name").Parse("Hello, {{.}}"))
Если Parse вернёт ошибку — программа упадёт с panic.
Используется, когда шаблон зашит в код и ошибка невозможна при нормальной работе.

✅ regexp.MustCompile
go
re := regexp.MustCompile(`\d+`)
Если регулярка некорректна — panic.
Удобно, когда выражение фиксировано и не зависит от внешнего ввода.

✅ cleanenv.MustLoadConfig
go
var cfg Config
cleanenv.MustLoadConfig("config.yml", &cfg)
Если файл не найден или структура невалидна — panic.
Используется, когда конфиг обязателен, и приложение не может работать без него.

🤔 Когда использовать Must
При инициализации, где ошибка — это фатальная ситуация.
Когда ты уверен, что ошибка невозможна (например, фиксированный шаблон).
В тестах, утилитах, CLI — где проще сразу упасть, чем обрабатывать ошибку.

в Golang что такое slog, зачем он, что позволяет делать, в чем его приемущества, какие есть альтернативы

slog — это новый пакет для структурированного и уровневого логирования, вошедший в стандартную библиотеку Go в версии 1.21 (golang.org/x/exp/slog в более ранних экспериментальных релизах). Он решает задачи, которые часто приходилось закрывать сторонними библиотеками: вывод полей (ключ–значение), уровни логов, настраиваемые обработчики (handlers) и форматтеры.

дефолтные логеры, текстовые, json
json - кибана, графана принимает логи


Основные возможности slog

Структурированное логирование
• Вместо простых строк вы логируете наборы ключ–значение:
logger.Info("user signed in", "user_id", uid, "ip", ipAddr)
• Поскольку поля типизированы, их можно легко сериализовать в JSON, logfmt, text…
Уровни логов (leveled logging)
• По умолчанию поддерживаются Debug, Info, Warn, Error и др.
• Можно фильтровать по уровню: в production — только Info+, в разработке — Debug+
Обработчики (Handlers) и форматтеры (Formatters)
• Вы настраиваете, как и куда будут идти логи.
• Например, ConsoleHandler (человекочитаемый) или JSONHandler (для сбора в ELK)
• Можно писать свои: менять поля, дописывать timestamp, трассировку…
Контекст и клонирование логгеров
• Из базового Logger можно «дочерний» разделенный общим контекстом:
go

Копировать код
reqLogger := logger.With("request_id", reqID)
reqLogger.Info("handling request", "path", r.URL.Path)
• Это удобно, чтобы в каждом сообщении автоматически указывался request_id, user_id и т. п.
Высокая производительность
• Пакет ориентирован на минимум аллокаций и копирований.
• Входит в stdlib — никаких внешних зависимостей.
Интеграция со стандартными primitive logger
• Можно оборачивать *log.Logger и наоборот.
• Обеспечить постепенный переход с log на slog.
Преимущества slog
• Стандартная библиотека: не нужно тянуть внешние пакеты, меньше зависимостей.
• Удобный и понятный API: уровни, ключ–значение, хендлеры.
• Гарантированная поддержка и совместимость Go-команды.
• Фокус на скорости и минимум аллокаций.

Что позволяет делать
• Писать структурированные логи без сторонних библиотек.
• Легко переключаться между форматами вывода (например, консоль vs JSON).
• Фильтровать логи по уровню.
• Делать «дерево» логгеров с общими полями.
• Интегрировать логирование с контекстом приложения.

Альтернативы slog (сторонние библиотеки)
• log (стандартный пакет) — простое текстовое логирование без уровней и полей.
• logrus (github.com/sirupsen/logrus) — один из самых популярных, структурированное, но имеет overhead.
• zap (go.uber.org/zap) — очень быстрая библиотека от Uber, ориентирована на нулевые аллокации.
• zerolog (github.com/rs/zerolog) — тоже zero-allocation JSON-логирование.
• apex/log (github.com/apex/log) — лёгкая обёртка над log, структурированное.
• go-kit/log (github.com/go-kit/log) — минималистичный logger, part of Go kit.

Когда стоит переходить на slog
• Если вы используете Go 1.21+ и вам нужен базовый структурированный логгер без новых зависимостей.
• Если вы хотите унифицировать формат и уровни логов, но не готовы переходить на большие решения типа Zap/Logrus.
• Если вам важна скорость и лёгкость интеграции со stdlib.

# 13
ERROR storage.sqlite.New: unable to open database file: no such file or directory

говорит о том, что драйвер SQLite не может найти (и создать) файл базы по указанному пути. Обычно такое бывает по одной из двух причин:

Неправильно указан путь (попытка открыть директорию, которой нет, или забыли сам файл).
Отсутствует директория, в которой вы хотите создать файл базы, и Go не создаёт каталоги «по умолчанию».
Как диагностировать и исправить

Проверьте путь (абсолютный или относительный) • Если вы передаёте в sql.Open("sqlite", "data/app.db"), то при go run база создастся рядом с текущей рабочей директорией (обычно корнем вашего проекта).
• Убедитесь, что вы запускаете приложение из той же папки, или дайте абсолютный путь:
go

Копировать код
dbPath := "/home/you/project/data/app.db"
Убедитесь, что директория существует При попытке открыть файл в папке data/, Go не создаст папку сам, и sqlite-пакет не сможет создать файл app.db.
До вызова .Open() создайте каталоги:
go

Копировать код
import (
    "database/sql"
    "log"
    "os"
    "path/filepath"

    _ "modernc.org/sqlite"     // или rsc.io/sqlite
)

func main() {
    dbPath := "data/app.db"

    // 1) Создаём директорию, если её нет
    dir := filepath.Dir(dbPath)
    if err := os.MkdirAll(dir, 0755); err != nil {
        log.Fatalf("failed to create directory %q: %v", dir, err)
    }

    // 2) Открываем (или создаём) базу
    db, err := sql.Open("sqlite", dbPath)
    if err != nil {
        log.Fatalf("unable to open database file: %v", err)
    }
    defer db.Close()

    // 3) Проверяем доступность
    if err := db.Ping(); err != nil {
        log.Fatalf("cannot ping database: %v", err)
    }

    // … дальше используете db …
}
Проверьте права доступа • Если путь указывает в системный каталог (или /var/...), убедитесь, что у пользователя есть права на запись.
• Для теста можно попробовать создать файл вручную в том же каталоге:
Code

Копировать код
touch data/app.db
ls -l data/app.db
Особенности DSN в разных драйверах – Для rsc.io/sqlite или modernc.org/sqlite DSN обычно — это просто путь без всяких параметров.
– В github.com/mattn/go-sqlite3 (CGO-драйвер) можно писать file:data/app.db?_foreign_keys=1, но всё равно сначала нужно, чтобы директория существовала.
Логи и подробности Если вам нужна более детальная диагностика, вы можете: • Вывести os.Getwd() в логи, чтобы понять, откуда вы запускаете приложение (например, через systemd рабочая папка может быть /).
• Печатать dbPath перед Open, чтобы не запутаться с относительными путями.
Итог:
– Проверьте и при необходимости замените на абсолютный путь или правильно относительный,
– создайте каталог(и) с помощью os.MkdirAll(),
– убедитесь в доступности прав,
– после чего sql.Open без ошибки создаст файл базы и откроет его.
